# Инструкция по тестированию LoveLetter

## ⚠️ Важно: Ограничения текущей версии

Текущая MVP-версия использует **localStorage** для хранения данных. Это означает:

- Приглашения хранятся **только в браузере**, где они были созданы
- Ссылки работают **только в том же браузере** на том же устройстве
- При открытии ссылки в другом браузере/устройстве приглашение не будет найдено
- Данные удаляются при очистке localStorage

## ✅ Как протестировать локально

### Вариант 1: Локальная разработка

```bash
# 1. Установите зависимости
npm install

# 2. Запустите dev-сервер
npm run dev

# 3. Откройте http://localhost:3000
```

**Шаги тестирования:**

1. Перейдите на главную страницу
2. Нажмите "Создать приглашение" или "Посмотреть примеры"
3. Выберите шаблон (например, "Валентинка")
4. Отредактируйте тексты в редакторе
5. Нажмите "Опубликовать"
6. Скопируйте ссылку (например, `http://localhost:3000/p/abc123`)
7. **Откройте эту ссылку в НОВОЙ ВКЛАДКЕ того же браузера**
8. Вы увидите интерактивное приглашение

### Вариант 2: Production-сборка

```bash
# 1. Соберите проект
npm run build

# 2. Запустите локальный сервер для статических файлов
npx serve dist -p 3000

# 3. Откройте http://localhost:3000
```

Тестирование аналогично варианту 1.

## 🌐 Деплой на Vercel

Проект настроен для деплоя на Vercel с правильной маршрутизацией SPA.

**Шаги:**

1. Загрузите код в GitHub
2. Импортируйте репозиторий в Vercel
3. Vercel автоматически определит Vite-проект
4. Нажмите Deploy

**После деплоя:**

- Создайте приглашение на `https://your-domain.vercel.app`
- Опубликуйте его
- Скопируйте ссылку
- Откройте в **том же браузере** (можно в новой вкладке)

**Ограничение:** Ссылка не будет работать в другом браузере или на другом устройстве, так как данные хранятся в localStorage конкретного браузера.

## 🔧 Почему так происходит?

В production-версии для полноценной работы необходимо:

1. **База данных** (Supabase PostgreSQL) для хранения проектов
2. **Аутентификация** (Supabase Auth) для пользователей
3. **Хранилище файлов** (Supabase Storage) для медиа
4. **Серверные функции** для публикации и доступа

Без этого приглажения привязаны к localStorage конкретного браузера.

## 🐛 Известные ограничения

1. **Данные хранятся в localStorage** — не работают между браузерами/устройствами
2. **Нет аутентификации** — любой может редактировать любые проекты в текущем браузере
3. **Нет загрузки медиафайлов** — только URL изображений
4. **Нет голосовых сообщений** — только текстовые элементы
5. **Нет реальной оплаты** — тарифы отображаются, но не работают
