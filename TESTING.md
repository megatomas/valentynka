# Инструкция по тестированию LoveLetter

## ✅ Как работают ссылки

**Приглашения работают между любыми браузерами и устройствами!**

Данные приглашения хранятся на удалённом сервере (npoint.io), поэтому:
- ✅ Ссылки короткие и удобные
- ✅ Ссылка работает в любом браузере
- ✅ Ссылка работает на любом устройстве (телефон, планшет, компьютер)
- ✅ Можно отправлять ссылку кому угодно через мессенджер, email, SMS
- ✅ Данные не хранятся в URL

**Технические детали:**
- Используется бесплатный JSON-хостинг npoint.io
- Не требуется регистрация или API-ключи
- Данные хранятся на сервере и доступны по короткому ID
- При повторной публикации данные обновляются (ссылка не меняется)

## 🚀 Как протестировать локально

### Вариант 1: Локальная разработка

```bash
# 1. Установите зависимости
npm install

# 2. Запустите dev-сервер
npm run dev

# 3. Откройте http://localhost:3000
```

**Шаги тестирования:**

1. Перейдите на главную страницу
2. Нажмите "Создать приглашение" или "Посмотреть примеры"
3. Выберите шаблон (например, "Валентинка")
4. Отредактируйте тексты в редакторе
5. Нажмите "Опубликовать"
6. Скопируйте ссылку (она будет длинной, это нормально)
7. Откройте эту ссылку в **любом браузере** на **любом устройстве**
8. Вы увидите интерактивное приглашение

**Тестирование кросс-браузерности:**

1. Создайте приглашение в Chrome
2. Скопируйте ссылку
3. Откройте её в Firefox, Safari или на телефоне
4. Приглашение должно работать везде!

### Вариант 2: Production-сборка

```bash
# 1. Соберите проект
npm run build

# 2. Запустите локальный сервер для статических файлов
npx serve dist -p 3000

# 3. Откройте http://localhost:3000
```

Тестирование аналогично варианту 1.

## 🔧 Как это работает?

Данные приглашения (тексты, сцены, настройки) сохраняются на удалённом сервере npoint.io. При публикации создаётся уникальный ID, который используется в короткой ссылке. Когда получатель открывает ссылку, данные загружаются с сервера и отображается приглашение.

**Преимущества этого подхода:**
- Короткие и удобные ссылки
- Работает между любыми браузерами и устройствами
- Не требуется регистрация или API-ключи
- При повторной публикации ссылка не меняется

**Ограничения:**
- Требуется интернет для загрузки данных
- npoint.io — бесплатный сервис, может быть менее надёжным для production
- Для production рекомендуется использовать Supabase или собственную базу данных

## 🐛 Известные ограничения

1. **Длинные URL** — ссылки могут быть очень длинными для больших проектов
2. **Нет аутентификации** — любой может редактировать проекты в текущем браузере (данные хранятся в localStorage)
3. **Нет загрузки медиафайлов** — только URL изображений
4. **Нет голосовых сообщений** — только текстовые элементы
5. **Нет реальной оплаты** — тарифы отображаются, но не работают

## 🚀 Что нужно для production (опционально)

Для более коротких ссылок и дополнительных возможностей можно подключить:

1. **База данных** (Supabase PostgreSQL) для хранения проектов — позволит использовать короткие ссылки
2. **Аутентификация** (Supabase Auth) для пользователей
3. **Хранилище файлов** (Supabase Storage) для медиа
4. **Серверные функции** для публикации и доступа
